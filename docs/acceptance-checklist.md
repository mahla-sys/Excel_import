# چک‌لیست معیار پذیرش نسخه‌ی اول

این چک‌لیست مستقیماً از بخش ۲۸ مشخصات پروژه گرفته شده و با پیشرفت کار
علامت‌گذاری می‌شود.

- [x] ۱. مدیر فنی یک مدرسه و یک حساب مسئول آن مدرسه می‌سازد.
      (`createsuperuser` + `create_school_operator` یا پنل ادمین)
- [x] ۲. مسئول مدرسه لاگین می‌کند و فقط اطلاعات مدرسه‌ی خودش را می‌بیند.
      (ایزولیشن در `SchoolScopedQuerySetMixin` + تست)
- [x] ۳. مسئول یک Excel با ساختار متفاوت آپلود می‌کند.
- [x] ۴. Sheet و ردیف Header را انتخاب می‌کند.
- [x] ۵. ستون‌های فایل را به فیلدهای استاندارد نگاشت می‌کند.
- [x] ۶. ستون‌های تکراری (نام/کدملی) را به دانش‌آموز، مادر و پدر نگاشت می‌کند.
      (تشخیص موقعیت + پیشنهاد هوشمند + UI)
- [x] ۷. سامانه داده‌ی خام و نرمال‌شده را جدا نگه می‌دارد.
- [x] ۸. کد ملی فارسی، عربی، خط‌دار یا دارای صفر ابتدایی درست بررسی می‌شود.
- [x] ۹. یک سطر ناقص کل Batch را خراب نمی‌کند.
- [x] ۱۰. مسئول می‌تواند سطر ناقص را بعداً تکمیل کند.
      (PATCH با اعتبارسنجی خودکار، دلیل برای فیلد حساس و ثبت در provenance)
- [x] ۱۱. دانش‌آموز بدون کلاس/شعبه ثبت می‌شود و وضعیت `pending_placement` می‌گیرد.
- [x] ۱۲. دو نام مشابه بدون کد ملی خودکار Merge نمی‌شوند.
      (تشخیص فقط هشدار است؛ هیچ merge خودکاری وجود ندارد + گردش‌کار Resolve)
- [x] ۱۳. مسئول گزارش Excel خطاها را دریافت می‌کند.
- [x] ۱۴. مسئول خروجی استاندارد Batch را دریافت می‌کند.
      (هم XLSX و هم JSON نسخه‌بندی‌شده با schema_version)
- [x] ۱۵. مسئول مدرسه الف هیچ‌وقت داده/فایل/گزارش مدرسه ب را نمی‌بیند.
- [x] ۱۶. فایل Excel خام عمومی نیست و فقط از مسیر مجاز دانلود می‌شود.
- [x] ۱۷. فایل خام، داده‌ی خام و تاریخچه‌ی Mapping برای مراجعه‌ی بعدی نگه‌داری می‌شوند.
- [x] ۱۸. هیچ داده‌ای به سیستم اصلی مدرسه منتقل نمی‌شود.
      (هیچ اتصال/مدلی به سیستم اصلی وجود ندارد؛ خروجی استاندارد با `external_code`)
