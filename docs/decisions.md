# تصمیم‌های معماری (Architecture Decisions)

این فایل تصمیم‌های مهم پروژه را ثبت می‌کند تا جلوتر چیزی فراموش نشود و
تغییرات بعدی آگاهانه انجام شود.

## ADR-001 — پروژه کاملاً مستقل از سیستم اصلی مدرسه

این پرتال در نسخه‌ی اول هیچ داده‌ای به سیستم اصلی منتقل نمی‌کند و به
دیتابیس یا API آن وصل نمی‌شود. خروجی فقط فایل‌های استاندارد نسخه‌بندی‌شده
است. یک Connector جداگانه در آینده این کار را انجام خواهد داد.

## ADR-002 — مونوریپو

```
/backend   # Django + DRF
/frontend  # React + Vite + TypeScript
/docs
```

هماهنگ‌سازی قرارداد API و استقرار را ساده می‌کند.

## ADR-003 — زبان فرانت‌اند TypeScript

تایپ-ایمنی برای کانترکت‌های API و داده‌ی حساس ارزشش را دارد.

## ADR-004 — احراز هویت با JWT در کوکی HttpOnly

- توکن‌های access و refresh در کوکی‌های `HttpOnly`, `Secure` (تولید)،
  `SameSite=Lax` نگه‌داری می‌شوند.
- هیچ توکنی در `localStorage` یا `sessionStorage` ذخیره نمی‌شود.
- CSRF با الگوی double-submit: یک توکن در کوکیِ قابل‌خواندن توسط JS
  (`csrf_token`) و در هدر `X-CSRFToken` برای درخواست‌های تغییر‌دهنده
  ارسال می‌شود. میدلور CSRF قبل از ویو اجرا می‌شود و مقدار هدر را با
  ادعای `csrf` داخل JWT مقایسه می‌کند.
- در فرانت، یک interceptor روی ۴۰۱ به‌طور خودکار یک‌بار refresh می‌زند
  و درخواست اصلی را تکرار می‌کند؛ در صورت شکست refresh کاربر به لاگین
  هدایت می‌شود. چند درخواست هم‌زمان فقط یک refresh ایجاد می‌کنند.

## ADR-005 — استقرار با Docker Compose

سرویس‌ها: `db` (postgres:16), `backend` (gunicorn), `frontend` (nginx که
`/api` را به backend پروکسی می‌کند). فایل‌های خصوصی و استاتیک در volume.
هیچ ادمین یا داده‌ی دمو به‌صورت خودکار ساخته نمی‌شود.

## ADR-006 — مدل کاربر سفارشی از ابتدا

`PortalUser` با فیلد `role` و `school_tenant` از همان migration اول ساخته
می‌شود. نقش‌ها: `system_admin`, `school_operator`. افزودن نقش
`school_approver` در آینده فقط افزودن یک مقدار به choices است و نیازی به
تغییر اسکیما ندارد.

## ADR-007 — فایل خام خارج از MEDIA_ROOT

ذخیره با نام UUID در مسیر `raw/<school_id>/<year>/<uuid>.xlsx`، بدون URL
عمومی، با مجوز `0640`. دانلود فقط از ویوی احراز هویت‌شده با کنترل مدرسه و
ثبت در AuditLog. نام اصلی فایل فقط در متادیتای دیتابیس است.

## ADR-008 — openpyxl فقط در حالت read_only

پانداس ممنوع است چون می‌تواند کد ملی/تلفن با صفر ابتدایی را به عدد تبدیل
کند. همه‌ی پردازش‌های اکسل با
`openpyxl.load_workbook(..., read_only=True, data_only=True, keep_links=False)`
انجام می‌شود و نمونه‌های ستون به‌صورت رشته استخراج می‌شوند تا صفرهای
ابتدایی حفظ شوند.

## ADR-009 — نرمال‌سازی و نگه‌داری مقدار خام کنار هم

برای هر فیلد مهم هم مقدار خام و هم مقدار نرمال‌شده نگه داشته می‌شود.
منشأ (Provenance) فیلد شامل شماره‌ی Batch، ردیف، ستون، برچسب ستون، مقدار
خام، مقدار نرمال و در صورت اصلاح دستی، ویرایش‌گر و دلیل است.

## ADR-010 — کد ملی کلید هویت؛ شباهت‌نام فقط هشدار

ادغام خودکار تحت هیچ شرایطی بر اساس نام یا شماره تلفن انجام نمی‌شود.
تکرار قطعی فقط با کد ملی معتبر گزارش می‌شود؛ شباهت نام/تاریخ/تلفن یک
`W-DUPLICATE-SUSPECTED` است که نیاز به بررسی انسانی دارد.

## ADR-011 — school_id هرگز از کاربر گرفته نمی‌شود

برای کاربران `school_operator` مدرسه همیشه از
`request.user.school_tenant` استخراج می‌شود. ارسال `school_id` در بدنه
یا کوئری توسط این کاربران نادیده گرفته می‌شود. فقط `system_admin`
می‌تواند در endpointهای مدیریتی با ارسال صریح `school` روی چند مدرسه کار
کند. تمام ویوهای مبتنی بر مدرسه از `SchoolScopedQuerySetMixin` استفاده
می‌کنند و باید همیشه یک `queryset` کلاسی داشته باشند تا میکسین کار کند.

## ADR-012 — پردازش هم‌زمان بدون Celery در MVP

فایل‌ها به‌صورت sync با `transaction.atomic` و savepoint به‌ازای هر سطر
پردازش می‌شوند. خطای یک سطر کل Batch را خراب نمی‌کند. سقف حجم (۱۰MB) و
تعداد سطر (۵۰۰۰) اعمال می‌شود. Gunicorn timeout روی ۱۲۰ ثانیه تنظیم
شده است.

## ADR-013 — سال تحصیلی به‌صورت دستی وارد می‌شود

`ImportBatch.academic_year_label` توسط مسئول مدرسه هنگام آپلود وارد
می‌شود (مثلاً `1405-1406`). سرور هرگز آن را از تاریخ روز استنتاج
نمی‌کند، چون فایل ممکن است مربوط به سال قبل یا ثبت‌نام سال آینده باشد.
فرانت می‌تواند سال جاری شمسی را به‌عنوان پیش‌فرض پیشنهاد دهد، اما تأیید
با کاربر است.

## ADR-014 — ستون‌های ناشناخته هرگز بی‌صدا حذف نمی‌شوند

هنگام نگاشت، هر ستون باید یکی از این وضعیت‌ها را داشته باشد:
`mapped_to_canonical_field`، `extra_attribute`، `ignored` (همراه با دلیل)
یا `requires_owner_decision`. پیش‌فرض، ذخیره در `extra_attributes` است.

## ADR-015 — اعتبارسنجی خودکار پس از اصلاح دستی

پس از هر ویرایش دستی روی یک StagedStudent، نرمال‌سازی و اعتبارسنجی همان
رکورد مجدداً اجرا می‌شود و خطاها/هشدارها و وضعیت به‌روز می‌شوند (بدون
نیاز به دکمه‌ی جدا). یک عملیات «بررسی مجدد کل Batch» برای تغییر Mapping یا
قانون جدید در سطح Batch وجود دارد.

## ADR-016 — source_student_code اختیاری است

کد پرونده/کد دانش‌آموزی مدرسه در صورت وجود ذخیره و به‌عنوان شناسه‌ی
کمکی استفاده می‌شود، اما فقدان آن مانع آپلود نیست. اگر کد ملی و
source_student_code هر دو نباشند، پرونده `incomplete` می‌ماند.

## ADR-017 — بایگانی هرگز حذف خودکار ندارد

Batchها و رکوردهای `archived` فقط علامت‌گذاری می‌شوند. حذف فیزیکی فقط
توسط یک Management Command محافظت‌شده یا از پنل ادمین و با ثبت صریح دلیل
در AuditLog ممکن است.

## ADR-018 — استک فرانت‌اند

React + TypeScript + Vite + Tailwind CSS + shadcn/ui + TanStack Query
(برای state سرور) + TanStack Table (برای جدول‌های سنگین، فیلتر و صفحه‌بندی)
+ React Hook Form. RTL و فونت Vazirmatn از ابتدا در Layout اعمال می‌شوند.
