# معیارهای عملکرد (Performance Benchmarks)

این اعداد انتظاری تقریبی برای MVP و پردازش **هم‌زمان (sync)** هستند.
اندازه‌گیری واقعی باید پس از پیاده‌سازی موتور نرمال‌سازی روی نمونه‌فایل‌های
واقعی مدارس انجام و این سند به‌روز شود.

| سناریو | سقف در MVP | زمان مورد انتظار |
|---|---|---|
| حجم فایل `.xlsx` | ۱۰ مگابایت | — |
| تعداد ردیف داده در هر Batch | ۵۰۰۰ ردیف | — |
| آپلود + کشف Sheet/Header | — | زیر ۲ ثانیه |
| پردازش کامل ۱۰۰۰ ردیف | — | زیر ۲ ثانیه |
| پردازش کامل ۵۰۰۰ ردیف | — | زیر ۱۰ ثانیه |
| دانلود گزارش خطا (۵۰۰۰ ردیف) | — | زیر ۵ ثانیه |
| Gunicorn worker timeout | ۱۲۰ ثانیه | — |

## راهکارهای مقیاس‌پذیری آینده

- بیش از ۵۰۰۰ ردیف: پردازش غیرهمزمان با Celery (در MVP ممنوع است).
- چند فایل هم‌زمان: افزایش تعداد Gunicorn workers یا انتقال پردازش به صف.
- رشد فایل‌های خصوصی: انتقال به S3-compatible object storage با همان
  لایه‌ی `PrivateFileSystemStorage` (رابط را ثابت نگه می‌داریم).
- گزارش‌های سنگین: تولید در پس‌زمینه و ارسال لینک امضاشده‌ی کوتاه‌مدت.

## محدودسازی آپلود

اعتبارسنجی سمت سرور در سه لایه انجام می‌شود:

1. **پیش از ذخیره**: پسوند `.xlsx`، امضای فایل (`PK\x03\x04`)، حجم ≤ ۱۰MB.
2. **پس از کشف Sheet**: تعداد ردیف داده ≤ ۵۰۰۰ (با شمارش واقعی).
3. **هنگام پردازش**: هر سطر در یک savepoint مستقل؛ خطای یک سطر کل Batch
   را خراب نمی‌کند.
